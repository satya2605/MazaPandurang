# Architectural Decision Record — DEC-2026-08-29-009: Tilak AI Foundation & Context Grounding

- **Status**: APPROVED
- **Date**: 2026-08-29
- **Deciders**: Platform Architecture Team, Satyajit (Pilgrim Module Lead)

## Context
Pilgrims participating in the Wari require intelligent assistance regarding Palkhi tracking, route stops, nearby medical camps, drinking water facilities, Dindi troupes, lost person cases, and emergency SOS dispatch.

## Decision
1. **Single Backend Endpoint**: `POST /api/ai/tilak/chat` exposed on shared Express REST API server, protected by Supabase JWT authentication (`authenticateJwt`).
2. **AI Provider Abstraction**: Vendor-neutral `AIProvider` supporting `DevAIProvider` (local rule/pattern engine), `GeminiAIProvider` (Google Gemini API), and `OpenAIAIProvider` (OpenAI API).
3. **Database Grounding & Security**: Server retrieves canonical database records from `palkhi_tracking`, `wari_route`, `services`, `dindis`, and `lost_person_reports`. Private credentials, storage URLs, or unapproved records are strictly excluded from AI prompts.
4. **Structured Action Navigation**: Response includes an array of `actions` (`{ type, id, label, targetRoute }`) rendered as interactive buttons in Flutter that trigger app navigation.

## Consequences
- Clean separation of concerns between Flutter UI and AI providers.
- Local development works deterministically without needing external API keys.
- Emergency requests safely route to native app SOS workflows.
